# CutPilot 파이프라인 설계 (멘토링용)

> 한 줄 요약: **AI는 "무엇을 할지" 계획만 세우고, 영상은 건드리지 않는다.**
> 계획 중 AI 혼자 정하면 안 되는 부분만 사용자에게 묻고, 사용자가 승인한 명세서대로만 로컬에서 편집한다.

---

## 1. 전체 흐름

```
 [사용자]  영상 업로드
              │
 ① 분석      프록시 영상(480p) 생성 → 사람 탐지·추적(YOLO + ByteTrack) → 얼굴 영역 추정
              │          결과: "누가 언제 어디에 있는가" (트랙)
              │
 [사용자]  "1. 가방 멘 사람 모자이크  2. 검은 모자 쓴 남자 중심으로 세로로"
              │
 ② 계획 해석  Gemini 호출 #1 (텍스트만)  → 편집 계획 초안 (JSON)
              │          "모자이크 / 대상: '가방 멘 사람' / 전체 구간"
              │
 ③ 대상 찾기  Gemini 호출 #2 (프레임 1장)  → "가방 멘 사람" = 어느 트랙?
              │          Gemini가 고르고, YOLO 박스로 확정
              │
 ④ 확인 정보  항목별 확신도(ok/confirm/choose) + 렌더링 전에 알 수 있는 경고
              │
 ⑤ 질문      AI가 정하면 안 되는 것만 하나씩 질문  ◀──┐
              │                                       │  답변: 버튼 / 박스 클릭 / 채팅
              │ ──────────────────────────────────────┘  (클릭은 AI 호출 없음)
              │
 ⑥ 명세서    "누가·무엇을·언제" + 확인한 내용  →  [승인]
              │
 ⑦ 렌더링    승인된 계획대로 모자이크·블러·세로 변환 → FFmpeg → 결과 영상
```

**AI 호출은 지시 한 번에 보통 2회** (계획 1회 + 지칭된 사람 수만큼 대상 찾기).
질문에 답하거나 화면을 클릭하는 건 AI를 다시 부르지 않는다.

## 2. 단계별 설명

### ① 업로드·분석 — "영상 속에 누가 언제 있나"

| 입력 | 처리 | 출력 |
|---|---|---|
| 원본 영상 (최대 180초) | 480p 프록시 변환, 썸네일 스프라이트 | 미리보기용 가벼운 영상 |
| 프록시 영상 | YOLO11n 사람 탐지 + ByteTrack 추적 | 트랙: `person_01`이 0~11.5초에 등장, 프레임별 박스 |
| 사람 트랙 | 박스 상단을 얼굴 영역으로 추정 | `face_01` (부모: `person_01`) |

- **왜 프록시로 추적?** 좌표를 0~1로 정규화해서 저장하므로 해상도가 달라도 같은 박스. 속도는 몇 배 빠르다.
- **분석은 업로드 때 한 번만.** 이후 모든 대화는 같은 트랙 id를 쓴다. 그래야 "아까 그 사람"이 항상 같은 사람이다.
- 얼굴은 **아직 추정**이다 (검출기 아님). 실제 얼굴 검출기를 넣어도 같은 형태(`face_XX`, 부모 연결)라 뒤 단계는 바뀌지 않는다.

### ② 계획 해석 — "무엇을 하라는 건가" (AI 호출 #1)

Gemini에 **글만** 보낸다. 이미지는 보내지 않는다.

```
보내는 것:  사용자 문장 + 화면 상태(재생 위치, 선택 구간) + 트랙 목록(누가 몇 초에 등장)
           + 현재 계획 + 최근 대화(에이전트가 한 질문 포함)
받는 것:   정해진 JSON 형식의 계획 초안
```

```json
{ "op": "MOSAIC",
  "selector": { "kind": "person", "include_phrases": ["가방 멘 사람"], "exclude_phrases": [] },
  "time_range": { "start": null, "end": null } }
```

- 사람을 **외모로 지칭**하면 표현 그대로 남긴다 ("가방 멘 사람"). 누구인지는 ③에서 본다.
- **시간으로 지칭**하면("처음부터 나온 사람") 트랙 목록의 등장 시간으로 바로 id를 정한다. 이미지가 필요 없다.
- AI 출력은 형식이 맞아도 의미가 틀릴 수 있어서 **코드로 한 번 더 정리**한다.
  - 예: "나머지 사람들"은 대상이 아니라 "전체"를 뜻한다.
  - 예: 세로 변환은 하나만 허용한다.
- 새 작업을 추가하면 기존 작업은 유지된다 (예: 모자이크 후 "세로로" → 둘 다 유지).

### ③ 대상 찾기 (Grounding) — "'가방 멘 사람'이 누구인가" (AI 호출 #2)

```
키프레임 선택  →  Gemini: "이 이미지에서 '가방 멘 사람'을 찾아 박스로"  →  YOLO 트랙 박스와 겹침(IoU) 비교
```

- **역할 분리: Gemini가 고르고, YOLO가 잰다.** Gemini 박스는 대략적이라 "누구인지" 판단에만 쓴다. 실제 편집 좌표는 모두 추적 결과에서 나온다.
- **키프레임:** 사용자가 보고 있던 화면(재생 위치)이 우선이다. 그 순간 대상이 없으면 사람이 가장 많은 순간을 고른다.
- **결과 판정 (확신도):**

| 상태 | 언제 | 다음 |
|---|---|---|
| `ok` | id로 직접 지칭했거나 이미 확정됨 | 묻지 않음 |
| `confirm` | 딱 한 명이 잘 맞음 | "이 사람 맞나요?" |
| `choose` | 여러 명이 맞거나, 박스가 두 사람에 걸쳐 구분 불가, 또는 못 찾음 | "누구인가요?" — **AI가 대신 고르지 않음** |

- **함정 차단:** 대상을 못 찾았을 때 대상 목록을 비우면 안 된다. "비어 있음 = 전체"라서, "그 남자만 가려"가 "모든 사람 가려"로 바뀐다. 그래서 "못 찾음" 표시(`?가방 멘 사람`)를 넣는다. 이 표시는 아무도 선택하지 않으므로 승인이 막힌다.
- 같은 표현은 세션 안에서 한 번만 찾는다. 다시 찾으면 비용이 들고 다른 사람을 고를 수도 있기 때문이다.

### ④ 확인 정보 — "렌더링해야 알 수 있는 문제를 미리"

계획 + 트랙만으로 계산하고 AI는 쓰지 않는다. 결과를 렌더링해서 봐야 알 수 있는 문제를 미리 경고한다.

| 경고 | 의미 | 왜 중요한가 |
|---|---|---|
| `track_gap` | 대상이 중간에 몇 초 사라짐 | 가려진 거라면 그 구간은 **모자이크가 안 됨 → 노출 사고** |
| `out_of_frame` | 세로로 자르면 대상이 화면 밖 | 효과를 줘도 결과에 안 보임 |
| `empty_selection` | 해당하는 대상이 없음 | 승인 불가 |

추가로 미리보기 박스 색상 정보(편집 대상 / 후보 / 제외 / 세로 변환 기준)도 만든다.

### ⑤ 질문 — "필요한 것만, 하나씩"

④의 결과를 **질문 큐**로 바꾼다. 계획 순서대로, 더 막히는 것부터 묻는다.

| 질문 | 막힘(blocking) | 답하는 법 |
|---|---|---|
| 누구인가요? (`choose`) | **예** | 후보 박스 클릭, 말로 설명, 작업 빼기 |
| 대상 없음 (`missing`) | **예** | 다시 설명, 작업 빼기 |
| 이 사람 맞나요? (`confirm`) | 아니오 | 맞아요 / 아니에요(→ "누구인가요?"로 바뀜) |
| 중간에 사라짐 (`track_gap`) | 아니오 | 그 구간도 이어서 처리 / 그대로 두기 |
| 세로 변환으로 잘림 (`out_of_frame`) | 아니오 | 유지 / 작업 빼기 |

- **막히는 질문은 버튼으로 넘길 수 없다.** AI가 사용자 대신 결정하지 않는다.
- "네" / "아니요"만 입력하면 **AI 호출 없이** 버튼과 같게 처리한다.
- 한 번 답한 질문은 계획을 고쳐도 다시 묻지 않는다.
- 사라진 구간 "이어서 처리"를 고르면 앞뒤 위치를 보간해 그 구간에도 박스를 만든다. 원본 분석 결과는 건드리지 않고 이 세션에만 적용한다.

### ⑥ 명세서와 승인 — "실행 전 마지막 확인"

질문이 다 끝나면 **최종 명세서**를 만든다.

```
최종 명세서
1. 모자이크 — 사람: person_09 (가방 멘 사람) — 전체 구간
2. 세로 변환 9:16 — 기준 인물 person_04 (검은 모자 쓴 남자) — 전체 구간
확인한 내용:
- '가방 멘 사람' → person_09
- '검은 모자 쓴 남자' = person_04 (확인)
```

- **승인 게이트 (코드로 강제):** 답하지 않은 질문, 못 찾은 대상, 빈 선택이 하나라도 있으면 승인이 거부된다 (HTTP 409 + 이유).
- 승인 후 계획을 조금이라도 고치면 승인이 풀린다.
- 각 작업은 켜고 끌 수 있다 (`enabled`). 완료 화면에서 작업을 숨기거나 복원하면 다시 렌더링한다.

### ⑦ 렌더링 — "승인된 계획만 실행"

```
원본 좌표에서 모자이크/블러 적용  →  (세로 변환이 있으면) 기준 인물을 따라 9:16으로 자르기  →  FFmpeg 인코딩
```

- **효과를 먼저, 자르기는 나중.** 가려야 할 사람이 자른 화면 경계에 걸쳐 있어도 확실히 가려진다.
- 세로 변환은 기준 인물 위치를 시간축으로 평균 내서 화면이 떨리지 않게 한다.
- 미리보기는 프록시(270×480)로 약 1초 걸리고, 내보내기는 원본 해상도로 같은 코드를 쓴다.

## 3. 대화 세션 — 무엇이 기억되나

| 기억하는 것 | 이유 |
|---|---|
| 현재 계획 + 각 표현의 대상 찾기 결과 | 수정할 때 다시 찾지 않음 (비용·일관성) |
| 대화 기록 (클릭 포함, 최근 6턴을 AI에 전달) | "아까 그 사람", "왼쪽 사람이요" 같은 답을 해석 |
| 답한 질문 목록 | 같은 질문 반복 방지 |
| 확인한 내용 (결정 기록) | 명세서에 표시 (감사 기록 역할) |
| 승인한 사람 이름표 | "검은 모자 쓴 남자" = person_04로 다음 지시부터 통함 |

**중요한 규칙:** "누구인가요?"가 열려 있을 때 사용자가 다른 걸 수정해도("5초까지만"), AI의 임시 추측이 확정된 것처럼 넘어가지 않는다. AI에게 보낼 때 임시 id를 원래 표현으로 되돌린다.

## 4. 안정성과 비용

| 장치 | 내용 |
|---|---|
| 재시도·대체 모델 | 일시 오류(429/5xx/시간 초과)는 재시도한다. 계속 실패하면 `gemini-3.6-flash` → `3.8-flash` 순으로 넘어간다 |
| 응답 캐시 | 같은 요청은 저장된 답을 쓴다. 비용 0, 결과도 재현 가능 |
| **비용 상한** | 토큰 수로 비용을 추정해 디스크에 누적하고, 상한($18)에 닿으면 AI 호출을 중단한다. 클릭 수정은 계속 가능 |
| 선불 크레딧 소진 | 402 또는 지출 상한 429를 받으면 재시도하지 않고 "크레딧 소진"이라고 안내한다 |
| 오프라인 모드 | API 키가 없으면 키워드 규칙으로 동작한다. 화면 개발·시연에 쓰고, 평가에는 쓰지 않는다 |

실측 비용: 계획 해석 1회 약 $0.003, 지시 1건(대상 찾기 포함) 약 $0.005 (원화 5~10원).

## 5. 평가 파이프라인

```
과제(문장 + 정답) → 같은 AI 응답 1회 →  ┬→ [확인 없음] 첫 계획 그대로 채점
                                       └→ [협상] 가상 사용자가 질문에 답하고 클릭으로 수정 → 채점
```

- 두 조건이 **같은 AI 응답을 공유**하므로, 차이는 순수하게 질문·확인 단계의 효과다.
- 핵심 지표는 **가려야 할 사람이 노출된 시간(초)**이다. 사람 판단 없이 숫자 하나로 비교할 수 있다.
- 첫 결과 (과제 16개): 확인 없음 94% → 협상 100%. 다만 **질문 15개 중 14개는 불필요**했다 (AI가 이미 맞힘).
- "텍스트만 vs 텍스트+화면" 비교는 사용자 실험으로 한다 (`?mode=text`).

자세한 내용: [`evaluation.md`](evaluation.md)

## 6. 설계 판단 — 예상 질문과 답

**Q. 왜 AI가 직접 편집 도구를 호출하지 않나요?**
A. 영상 편집은 비싸고 되돌리기 어렵습니다. AI는 검토할 수 있는 계획(JSON)만 만들고, 실행은 사람이 승인한 뒤 코드가 합니다. AI의 실수가 결과물로 바로 이어지지 않습니다.

**Q. 왜 AI 호출을 두 번으로 나눴나요?**
A. 대부분의 해석(무엇을, 언제, 시간 기준 지칭)은 글만으로 됩니다. 이미지는 외모로 지칭할 때만 필요합니다. 나누면 비용이 줄고, 어느 단계에서 틀렸는지 따로 측정할 수 있습니다.

**Q. Gemini가 박스를 주는데 왜 YOLO를 또 쓰나요?**
A. Gemini 박스는 한 장면의 대략적인 위치일 뿐입니다. 편집에는 매 프레임의 정확한 위치가 필요하고, 그건 추적기가 줍니다. Gemini는 "누구"만 고릅니다.

**Q. 왜 매번 확인하지 않고 일부만 묻나요?**
A. 다 물으면 사용자가 지칩니다. 실측에서도 AI가 대부분 맞혔습니다. 정말 모호하거나 틀리면 사고가 나는 경우에만 묻는 것이 목표이고, 이게 이 프로젝트의 핵심 주장입니다.

**Q. 기존 AI 편집 도구와 뭐가 다른가요?**
A. "실행 전 확인" 자체는 새롭지 않습니다. 차별점은 세 가지입니다.
1. 계획을 사용자가 고치는 단위(작업 / 대상 / 구간)로 쪼갰습니다.
2. 불확실성 종류에 따라 개입 강도를 다르게 했습니다 (묻지 않음 / 확인 / 선택).
3. 말과 클릭 두 가지 수정 경로를 제공하고, 그 효과를 노출 시간으로 측정합니다.

## 7. 현재 한계와 다음 단계

| 한계 | 다음 단계 |
|---|---|
| 얼굴은 사람 박스 윗부분으로 **추정** | 얼굴 검출기(YuNet) 도입, 얼굴이 크게 나오는 영상 확보 |
| 번호판 처리 미구현 | 범위에서 제외하거나 후순위 |
| 불필요한 "맞나요?" 질문이 많음 | 확신이 높은 단일 매칭은 묻지 않고 명세서에만 표시하는 방안 검토 |
| 평가 규모 (영상 1개, 과제 16개, 라벨 미검수) | 어려운 영상 2~3개 추가, 과제 40개 이상, 라벨 검수 |
| 사용자 실험 미실시 | 참가자 10명 이상, 텍스트만 vs 텍스트+화면 |
